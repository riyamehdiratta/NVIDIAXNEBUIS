# Extraction evaluation

The evaluation corpus is generated locally by `backend/evals/extraction_eval.py`. It contains 60 synthetic notes: 30 labeled as containing one open commitment and 30 hard-negative examples that mention action words in examples, definitions, negations, or historical text. The metric is source-level classification: a source is a true positive when the extractor returns a candidate linked to its source ID.

Run local heuristics:

```powershell
.\.venv\Scripts\python.exe -m backend.evals.extraction_eval
```

Run the optional Nemotron 3.5 Lightning comparison (synthetic text only; asks for terminal confirmation and writes request receipts to the local egress ledger):

```powershell
.\.venv\Scripts\python.exe -m backend.evals.extraction_eval --remote
```

## Current result

| Extractor | Corpus | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Local heuristic | 60 synthetic sources | 30 | 30 | 0 | 0.500 | 1.000 | 0.667 |
| Nemotron 3.5 Lightning | Not run | - | - | - | - | - | - |

The result exposes the local heuristic's intended bias: it catches all positive examples in this small corpus but also treats action-word mentions in hard negatives as candidate work. It is not a representative user dataset and should not be used to claim production precision or recall. The synthetic corpus and labels are generated by the same script; improve coverage with independently authored examples before drawing broader conclusions.

Nebius model IDs were checked against the official [Nebius Token Factory Nemotron cookbook](https://github.com/nebius/token-factory-cookbook/tree/main/models/nemotron): `nvidia/Nemotron-3_5-Lightning` and `nvidia/nemotron-3-super-120b-a12b`. The catalog check is not a live inference test. Model behavior and latency have not been measured yet.
